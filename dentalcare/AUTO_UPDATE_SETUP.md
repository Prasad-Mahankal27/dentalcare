# Orisyn Auto Update (GitHub Releases)

This project uses a hybrid architecture:

1. GitHub Releases as the source of truth for versions and installers.
2. A website page that fetches latest release metadata dynamically.
3. Electron app auto-update with `electron-updater`.

Production website:

`https://orisyn.parallaxstudio.co.in/`

## Desktop App (Electron)

Current implementation:

1. Checks updates on app startup using `autoUpdater.checkForUpdatesAndNotify()`.
2. Auto-downloads updates in background.
3. Installs as soon as update is downloaded (`autoUpdater.quitAndInstall()`).
4. Exposes updater status and manual check via IPC for Settings page.

Config location:

1. `dentalcare/electron-builder.json5`
2. `publish.provider = github`
3. `publish.owner = parallaxstudioco`
4. `publish.repo = Orisyn`

## Required Environment Variables

For publishing releases:

1. `GH_TOKEN=<github-personal-access-token-with-repo-access>`

## Release Workflow

Use semantic tags and releases (`v1.0.0`, `v1.1.0`, etc.).

Commands:

1. `npm --prefix dentalcare version 2.0.0 --no-git-tag-version` (or patch/minor/major for next releases)
2. `npm --prefix dentalcare run dist:publish`

Automated release pipeline:

1. `.github/workflows/release.yml` publishes installers on tags matching `v*`.
2. Create a Git tag like `v1.2.0` and push it to trigger CI publishing.

Optional platform-specific publish commands:

1. `npm --prefix dentalcare run dist:mac:publish`
2. `npm --prefix dentalcare run dist:win:publish`

Published release assets should include:

1. Windows installer (`.exe`)
2. macOS installer (`.dmg`)
3. Update metadata generated by electron-builder (`latest.yml`, `latest-mac.yml`, blockmaps)

## Website Dynamic Download Buttons

A minimal website implementation is provided in:

1. `website/index.html`
2. `website/latest-release.js`

It fetches from:

`https://api.github.com/repos/<owner>/<repo>/releases/latest`

Behavior:

1. Updates displayed latest version (`tag_name`).
2. Resolves `.exe` asset URL for Windows button.
3. Resolves `.dmg` asset URL for Mac button.
4. Optionally hides non-matching OS button based on browser platform.

## Constraints Followed

1. No custom update server.
2. No `version.json`.
3. GitHub Releases is the single source of truth.
4. Website links are resolved dynamically from GitHub API.

## Production Notes

1. Sign macOS and Windows builds for smooth updater behavior.
2. Keep GitHub releases public if clients are unauthenticated.
3. Do not remove `.zip` target for macOS because updater needs it.
